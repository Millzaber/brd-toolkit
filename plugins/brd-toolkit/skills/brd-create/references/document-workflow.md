# การสร้าง DOCX โดยคงแบบฟอร์ม

1. ใช้เครื่องมือ DOCX ที่มีในระบบ หากมี workspace dependency loader หรือ Documents skill ให้ใช้เพื่อหา Python และ renderer ปัจจุบัน มิฉะนั้นใช้ Python 3 พร้อม python-docx และ LibreOffice ห้าม hardcode path เฉพาะเครื่อง
2. ทำสำเนา assets/mini-brd-master.docx ไปยังพื้นที่งาน หากมีเครื่องมือ template-distill/template-create ให้ใช้ โดยเก็บไฟล์ทำงานแยกและไม่เขียนทับ reference
3. แก้ด้วย python-docx หรือ OOXML โดยรักษา pPr/rPr, numbering, styles, section, header/footer, images และ relationships เดิม หลีกเลี่ยง paragraph.text = ... กับย่อหน้าที่มี label ตัวหนาและ value ปกติ ให้เปลี่ยน runs ของ value หรือสร้าง runs ใหม่ที่สืบทอดรูปแบบจากบทบาทเดิม
4. P11 มีทั้งหัวข้อและเนื้อหาในย่อหน้าเดียวกัน ต้องเก็บหัวข้อ Scope of Work และแทนเฉพาะเนื้อหา เพิ่ม FR/AC โดย clone รูปแบบรายการเดิม แล้วแทนเนื้อหาทั้งรายการ ห้ามทิ้ง FR/AC ตัวอย่างต่อท้าย
5. ตั้ง font ของข้อความใหม่ทุก script slot (`ascii`, `hAnsi`, `eastAsia`, `cs`) เป็น `TH SarabunPSK` และขนาด `sz`/`szCs` เป็น 28 half-points (14 pt) ป้องกันภาษาไทยตกไปใช้ complex-script font อื่น เก็บ bold ของหัวข้อ/label และรูปแบบตารางตามต้นฉบับ เนื้อหาใต้หัวข้อเป็นตัวปกติ ใช้ bold เฉพาะรหัส FR/AC และคำหรือเงื่อนไขสำคัญที่ต้องเน้น ไม่ทำเนื้อหาทั้งย่อหน้าเป็นตัวหนา และไม่เปลี่ยนโลโก้เป็นข้อความ
6. เก็บ PAGE/NUMPAGES fields ใน footer และอัปเดตค่าแสดงผลด้วย renderer ไม่ hardcode จำนวนหน้า เก็บตารางอนุมัติให้อ่านต่อเนื่อง ไม่แบ่งแถวกลางลายเซ็น หากหัวข้ออยู่ท้ายหน้าโดยไม่มีเนื้อหาตามให้ใช้ keep-with-next เฉพาะจุด ไม่ย่อฟอนต์ทั้งเอกสาร
7. ตรวจข้อความทั้ง body, tables, header/footer และองค์ประกอบข้อความอื่นว่าค่าของงานตัวอย่างไม่ตกค้าง (ยกเว้นผู้ใช้ระบุค่าเดียวกันจริง) ตรวจลิงก์ FR–AC และหัวข้อครบ
8. Render DOCX ด้วย renderer ที่ระบบมี เช่น Documents render_docx.py หรือ LibreOffice แล้วตรวจภาพทุกหน้าและแก้จนไม่มีไทยหาย ข้อความชน ขอบตารางขาด หรือหน้าว่างเกินจำเป็น อย่าระบุว่า QA ผ่านจากการอ่านข้อความ XML อย่างเดียว

## ฟอนต์และ renderer

ชื่อฟอนต์ในเอกสารคือ TH SarabunPSK ต้องใช้ฟอนต์นี้ตามผู้ใช้ ไม่สลับเป็น TH Sarabun New เงียบ ๆ
ผู้ติดตั้งต้องมีฟอนต์ TH SarabunPSK ที่ได้รับอนุญาตในระบบ หาก headless LibreOffice มองไม่เห็นฟอนต์ ให้สร้าง `FONTCONFIG_FILE` ชั่วคราวที่ชี้ไปยังโฟลเดอร์ฟอนต์ของระบบและ cachedir ที่เขียนได้ โดยไม่เปลี่ยน HOME หรือ runtime ส่วนกลาง ถ้าไม่มีฟอนต์หรือ renderer ให้แจ้งข้อจำกัดตรง ๆ และอย่าอ้างว่ารูปแบบผ่านการตรวจแล้ว
